# CHANGELOG — Go to Top Telegram Bot

## v2.0.0 (2026-04-02) — Critical Bug Fixes

### BUG 1: AI не запоминал диалог (КРИТИЧЕСКИЙ)
ПРОБЛЕМА: Каждое сообщение отправлялось как отдельный запрос без контекста. Бот забывал всё сразу.
ИСПРАВЛЕНИЕ: Добавлен класс ConversationHistory — хранит последние 12 сообщений (6 пар) для каждого клиента. AI теперь помнит имя, артикул, данные, и ведёт клиента по воронке.

### BUG 2: Бот зависал (КРИТИЧЕСКИЙ)
ПРОБЛЕМА: API-вызов к Groq без таймаута. Если Groq не отвечал — бот зависал навсегда.
ИСПРАВЛЕНИЕ: Добавлен asyncio.wait_for с timeout=30 секунд. При таймауте — переход к следующей модели/ключу.

### BUG 3: Менеджер-чат сломан (КРИТИЧЕСКИЙ)
ПРОБЛЕМА: FSM-состояния конфликтовали. Клавиатура после отключения показывала «Меню» на всех кнопках. Сообщения маршрутизировались неправильно.
ИСПРАВЛЕНИЕ: Полностью переписан handlers/manager.py:
- Разделена логика: менеджер хранит active_user_id, клиент хранит connected_manager_id
- In-memory tracking через active_connections dict
- Правильная очистка FSM при завершении обеими сторонами
- Клавиатура после отключения использует реальный i18n с языком клиента
- Защита от подключения к нескольким клиентам одновременно

### BUG 4: Старый промпт со звёздочками
ПРОБЛЕМА: В коде был промпт v1 с **markdown** форматированием — 555 строк встроенного текста.
ИСПРАВЛЕНИЕ: Промпт загружается из внешнего файла liya_prompt_v4_final.md. Содержит: новый промпт без звёздочек, активацию ключевых слов, расчёт стоимости, правильные формулировки про реальных людей.

### BUG 5: ParseMode.HTML ломал AI-ответы
ПРОБЛЕМА: Бот был настроен на ParseMode.HTML, но AI отвечает plain text. Символы < > & ломали сообщения.
ИСПРАВЛЕНИЕ: Убран ParseMode.HTML из DefaultBotProperties. Все message.answer() теперь с parse_mode=None.

### BUG 6: Нет обработки ошибок отправки
ПРОБЛЕМА: Если ответ AI содержал спецсимволы — message.answer() падал молча.
ИСПРАВЛЕНИЕ: Добавлена функция send_safe() — ловит ошибки, обрезает длинные сообщения, отправляет fallback.

### BUG 7: Язык не сохранялся в БД
ПРОБЛЕМА: Выбор языка хранился только в FSM (в памяти). После перезапуска все сбрасывались на русский.
ИСПРАВЛЕНИЕ: set_language() теперь вызывает update_user_language() для записи в БД.

### BUG 8: Несуществующие модели
ПРОБЛЕМА: В списке fallback моделей была llama-3.1-405b-reasoning — её нет на Groq.
ИСПРАВЛЕНИЕ: Список моделей: llama-3.3-70b-versatile, llama-3.1-70b-versatile, llama-3.1-8b-instant.

### Новая функция: Автоматическое обнаружение заявки
AI может пометить собранные данные тегом [LEAD_READY]. Бот парсит этот тег, извлекает данные и отправляет менеджеру структурированную заявку с кнопкой «Подключиться».

### Новая функция: Очистка истории при /start
При нажатии /start история AI-диалога очищается — клиент начинает с чистого листа.

## Изменённые файлы:
- bot.py — убран ParseMode.HTML
- services/ai_service.py — полностью переписан (история, таймаут, новый промпт, модели)
- handlers/ai_support.py — history, lead detection, send_safe, parse_mode=None
- handlers/manager.py — полностью переписан (FSM, маршрутизация, клавиатура, i18n)
- handlers/common.py — язык в БД, parse_mode=None, clear_history на /start
